# 套汇程序大纲：C++ / STL 四人填写版

对应附件第13题。此工程提供数据结构、统一接口、命令行菜单、网页工作台和示例数据。11 个核心业务函数保留 TODO，由四位成员填写。网页可以预览和编辑图草稿。C++ 业务以对应模块的实际返回状态为准，未填写的函数返回 `Status::NotImplemented`。

## 网页工作台

在仓库根目录运行以下两条命令。需要 Node.js 18+ 和可在当前终端执行的 `g++`。Windows 可使用 MinGW-w64，将对应的 `bin` 加入当前终端的 PATH。

```sh
npm run build
npm start
```

打开 [http://127.0.0.1:4173](http://127.0.0.1:4173)。项目没有 npm 依赖，构建会同时生成控制台程序 `build/arbitrage` 和网页适配程序 `build/arbitrage_web`，Windows 文件后缀为 `.exe`。有 CMake 的环境也可运行 `cmake -S . -B build` 和 `cmake --build build --config Release`，再运行 `npm start`。

默认示例绘制 USD、GBP、FRF 及兑换方向。可切换六组原始样例，拖动或缩放图面，编辑币种与单向汇率，并导入或下载 TXT 草稿。兑换边表可以直接打开汇率编辑或删除单向边。删除币种会一并删除关联的兑换边，编辑区可撤销最近一次删除或清空。示例预期与实际运行结果各自有明确标记。用 C++ 接口复核过的盈利闭环会同时在有向图和兑换边表中标出，计算结果包含路径、逐步金额、利润及收益率。

只浏览和编辑草稿时可直接运行 `npm start`。如果希望用静态网页服务器预览，从仓库根目录对外提供文件，并打开 `web/` 入口。静态入口读取同仓库的 `data/` 样例，原生接口按钮显示为静态预览状态。连接 C++ 需使用上面的本地启动方式。网页服务只监听本机，默认端口 **4173**，可通过环境变量 `PORT` 调整。已应用的自定义草稿会保存在当前浏览器，刷新后自动恢复，切换样例后也可选回“自定义草稿”。需要把草稿带到其他浏览器或设备时，可以下载 TXT。

## 1. 先确认题目中的图模型

原题要求“基于STL的有向无环图”，但其示例是“美元→英镑→法郎→美元”。若币种作为顶点，回到原币种的兑换路线必然构成环，因此该表述存在矛盾。

**本大纲采用允许有环的有向带权图，需要向教师核实原题的“无环”是否为笔误。** 本框架不满足字面上的DAG限制；若教师坚持DAG，需要另行引入兑换次数等条件重新建模，不能直接沿用这里的负环算法。

项目目标：在题目给定的固定汇率模型下，检测套汇机会，并输出一条经过收益复核的兑换闭环、逐步金额和收益率。收益计算不包含手续费、额度或汇率随交易变化等扩展因素。

## 2. 基本思路

币种对应顶点，可用兑换方向对应有向边，边上保存原始汇率。例如 `USD GBP 0.7` 表示1美元可兑换0.7英镑。

一条闭环可以盈利，当且仅当这一圈的汇率乘积大于1：

$$r_1r_2\cdots r_k > 1.$$

对每条边设置权重：

$$w(u,v)=-\ln r(u,v).$$

由对数性质，有：

$$r_1r_2\cdots r_k>1\iff\sum_{i=1}^k-\ln r_i<0.$$

因此可以使用Bellman–Ford寻找负环候选，再恢复兑换路线并复核收益。目标是找出一条合格闭环；在固定汇率且允许无限重复兑换的理想模型中，盈利环可以不断复用，不能把“无限次兑换下的有限最大利润”作为基础目标。

## 4. 共用数据结构

```cpp
struct ExchangeEdge {
    int from = -1;
    int to = -1;
    long double rate = 0.0L;
};

struct ExchangeGraph {
    std::vector<std::string> currencies;
    std::unordered_map<std::string, int> index;
    std::vector<ExchangeEdge> edges;
};
```

`currencies` 的下标是币种编号，`edges` 的下标是边编号。原始汇率始终保留，负对数权重按需生成，避免修改汇率后缓存权重失效。

检测结果包含三个关键字段：

```cpp
struct DetectionResult {
    bool hasCandidate = false;
    int witnessVertex = -1;
    std::vector<int> predecessorEdge;
};
```

`predecessorEdge[v]` 记录指向顶点v的前驱边编号，无前驱时为-1。使用边编号能够明确恢复时实际采用的是哪条兑换边。`ExchangeCycle::edgeIds` 保存实际兑换方向的边序列，`ArbitrageReport` 保存步骤、初始金额、最终金额、利润和收益率。

所有输出参数只在函数返回 `Status::Ok` 时有效。占位函数不能返回 `false` 冒充“没有套汇”，也不能把初始化的空路径或零利润当作已计算结果。

## 6. 第2人：负环检测

### B1：buildLogWeights

检查图是否合法，为每条边计算 `-std::log(rate)`。返回的权重数组顺序必须与 `graph.edges` 一致；不得覆盖原始汇率。空图可返回成功和空权重。

### B2：detectArbitrage

实现方向：

1. 调用B1取得权重；空图返回EmptyGraph。
2. 将所有顶点的距离初始化为0，等价于增加一个可到达所有顶点的超级源点，覆盖不连通分量。
3. 将前驱边数组初始化为-1。
4. 最多执行n轮松弛，n为币种数。某轮没有更新时可提前结束。
5. 每次松弛成功时，记录目标顶点对应的前驱边编号。
6. 第n轮仍有更新时，记录该轮最后更新的顶点，设置hasCandidate为true。
7. 否则返回Ok和hasCandidate=false，witnessVertex保持-1。

本框架约定的松弛比较为：

```cpp
newDistance < distance[to] - RELAX_EPS
```

算法复杂度为O(nm)，m为边数。浮点容差会影响极小收益的识别，因此菜单表述为“在当前浮点容差下未检测到负环”。有币种但没有兑换边时，返回成功和无候选。

## 7. 第3人：恢复环与收益

### C1：recoverCycle

从检测返回的witnessVertex出发，沿前驱边的起点方向走n步，先进入环，再收集环上的边。前驱回溯的方向与实际兑换方向相反，收集后需要反转边编号列表。

必须检查：

- 检测结果确实包含候选，前驱数组大小为n。
- 每个顶点和前驱边编号有效，前驱边的终点等于当前顶点。
- 进入环后，在不超过n条边的范围内回到起点。
- 反转后的相邻边首尾相接，末边终点等于首边起点。

恢复出的环可以从任意币种开始；同一环的不同旋转都正确。检测、恢复和收益计算使用同一张未修改的图，不能复用改图前的边编号。

### C2：evaluateCycle

检查初始金额有限且大于0，检查闭环，再复核其收益：

$$\text{logGain}=\sum\ln r_i,$$

$$\text{logGain}>\ln(1+\text{PROFIT\_EPS}).$$

阈值比较可用 `std::log1p(PROFIT_EPS)`；收益率可用 `std::expm1(logGain)`。报告里的profitRate按比例保存，例如0.064表示6.4%，由主程序乘100后展示。

逐步记录每次兑换的币种、汇率和前后金额，给出最终金额及利润。金额连乘、最终收益和显示结果均要检查可表示性；溢出、下溢为0或非有限结果返回NumericError，不能错误报告“没有套汇”。

### 候选与最终结论的区别

第n轮更新给出负环候选，但候选不一定超过最终收益阈值。此时返回BelowProfitThreshold，表示“本次候选未通过”，**不能据此断言全图不存在其他达到阈值的盈利环**。当前接口查找并复核一个候选；全面搜索所有超过阈值的环属于后续扩展。

默认参数：RELAX_EPS=1e-12，PROFIT_EPS=1e-10。它们是框架的数值约定，不能保证识别任意微小的真实收益。

- n、m为合法范围内整数，`0 0`是合法空图。

- 同向重复边返回DuplicateRate，不能悄悄覆盖文件中的前一条。
- 数字必须完整解析；缺少字段、多余内容或非法汇率都要拒绝。
- 全部解析成功前不覆盖原图，避免只导入一半。
